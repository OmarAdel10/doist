> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire the Phase 1 STT and Phase 2 LLM Blocs into the HomeTab UI (mic FAB → record → transcribe → task; AI action chips → LLM → task list), add a Settings API-key input section (Groq + Google AI keys stored via `flutter_secure_storage`), and ship UI/UX enhancements (empty state, priority chips, haptics, pull-to-refresh).

**Architecture:** Three UI wiring layers: (1) Settings `ApiKeySection` → `SettingsBloc` → `SecureStorage` for API key persistence; (2) HomeTab `MicFab` → `SttBloc` → `GroqSttService` → `HomeTabAddAiTask` for voice task entry; (3) HomeTab `AiActionChip`s → `LlmBloc` → `GeminiLlmService` → `HomeTabAddAiTask`/`HomeTabReplaceTasks` for AI task management. UI/UX stays in `lib/home_tab/view/` and `lib/settings_tab/view/`.

**Tech Stack:** Flutter 3.47.6 / Dart 3.13.5; existing deps (`flutter_secure_storage`, `google_generative_ai`, `http`, `record`, `bloc`, `flutter_bloc`, `hydrated_bloc`, `flutter_animate`, `flutter_slidable`); `bloc_test` + `mocktail` for tests.

**Spec:** No existing spec file. This plan is the spec. Per SOUL §5, no out-of-scope features beyond AI wiring + the listed UI/UX items.

## Review Focus (inputs/failure modes most likely to bite)

1. Missing microphone permission → audio recording crashes; handle `record` permission errors gracefully with fallback UI.
2. Missing/invalid Groq or Google AI key → LLM feature disabled silently, app still usable (no hard crash, no key leaked).
3. STT `recordAndTranscribe` blocks UI → must run via `SttBloc` (async), not block the UI thread.
4. LLM returns malformed JSON → `LlmError` state, UI shows retry + "add key in Settings" hint.
5. Empty task list after delete/all-checked → empty-state widget must render instead of blank screen.
6. `flutter_secure_storage` reads are async — UI must handle loading state before showing AI features.
7. API keys lost on app uninstall — acceptable; user re-enters in Settings.
8. Pull-to-refresh + BLoC state — refresh should not double-emit; use `RefreshIndicator` with `onRefresh` that triggers no-op or re-emits current state.

  ```dart
  class SettingsModel {
    final ThemeMode themeMode;
    final String language;
    final bool isOnBoardingDone;
    final String? groqApiKey;
    final String? googleAiApiKey;

    const SettingsModel({
      required this.themeMode,
      required this.language,
      required this.isOnBoardingDone,
      this.groqApiKey,
      this.googleAiApiKey,
    });

    SettingsModel copyWith({
      ThemeMode? themeMode,
      String? language,
      bool? isOnBoardingDone,
      String? groqApiKey,
      String? googleAiApiKey,
    }) {
      return SettingsModel(
        themeMode: themeMode ?? this.themeMode,
        language: language ?? this.language,
        isOnBoardingDone: isOnBoardingDone ?? this.isOnBoardingDone,
        groqApiKey: groqApiKey ?? this.groqApiKey,
        googleAiApiKey: googleAiApiKey ?? this.googleAiApiKey,
      );
    }

    Map<String, dynamic> toMap() {
      return <String, dynamic>{
        'themeMode': themeMode.name,
        'language': language,
        'isOnBoardingDone': isOnBoardingDone,
        'groqApiKey': groqApiKey,
        'googleAiApiKey': googleAiApiKey,
      };
    }

    factory SettingsModel.fromMap(Map<String, dynamic> map) {
      return SettingsModel(
        themeMode: ThemeMode.values.firstWhere(
          (e) => e.name == map['themeMode'],
          orElse: () => ThemeMode.light,
        ),
        language: map['language'] as String,
        isOnBoardingDone: map['isOnBoardingDone'] as bool,
        groqApiKey: map['groqApiKey'] as String?,
        googleAiApiKey: map['googleAiApiKey'] as String?,
      );
    }

    @override
    List<Object?> get props => [themeMode, language, isOnBoardingDone, groqApiKey, googleAiApiKey];
  }
  ```

  ```dart
    SettingsBloc(this._secureStorage) : super(...) {
      on<SettingsSaveApiKeys>((event, emit) async {
        await _secureStorage.write(SecureStorageKeys.groqApiKey, event.groqApiKey);
        if (event.googleAiApiKey != null) {
          await _secureStorage.write(SecureStorageKeys.googleAiApiKey, event.googleAiApiKey!);
        }
        emit(SettingsUpdateState(model: state.model.copyWith(
          groqApiKey: event.groqApiKey,
          googleAiApiKey: event.googleAiApiKey,
        )));
      });
    }
  ```

## Risks, Tradeoffs, Open Questions

**Risks:**
- Groq Whisper requires microphone permission — Android `RECORD_AUDIO` + iOS `NSMicrophoneUsageDescription` already added in Phase 1.
- Free-tier rate limits on Groq/Google AI — UI should show graceful degradation, not crash.
- `flutter_secure_storage` reads are async — UI must handle loading state before showing AI features.
- API keys never leave device; if user uninstalls app, keys are lost (acceptable — re-enter in Settings).

**Tradeoffs:**
- Single `LlmBloc` for 3 capabilities vs. separate blocs — chosen for simplicity.
- `ApiKeySection` reads keys from `SecureStorage` on init — async loading state needed.
- `MicFab` takes `SttBloc` directly — could use `BlocProvider.of` instead but constructor injection is more testable.

**Open questions (confirm with user before execution):**
1. API key Settings: Groq key only, or Groq + Google AI keys?
2. Should the mic FAB be a floating action button or an icon button in the app bar?
3. Should AI chips appear inline in HomeTab or in a bottom sheet/dialog?
4. Should `SecureStorage` keys be added for Google AI API key too?
